# Datason 2.0.0a2

Prepared October 4, 2026. These alpha release notes cover changes since
[v2.0.0a1](https://github.com/danielendler/datason/releases/tag/v2.0.0a1).

Datason remains a pure Python serializer with no required runtime dependencies.
This alpha hardens data boundaries, improves supported scientific round trips,
and adds an opt-in LangGraph checkpoint adapter. Python 3.10+ remains required.

## Highlights

- **Scientific fidelity:** NumPy scalars retain supported dtype widths, including
  unsigned integers and complex values. Arrays preserve empty and zero-dimensional
  shapes; datetime64/timedelta64 values retain units. Pandas metadata preserves
  supported indexes, labels, column dtypes, categories and timestamp precision.
  NumPy complex128 dispatch also works when warnings are treated as errors.
  See the [scientific fidelity contract](https://github.com/danielendler/datason/blob/v2.0.0a2/docs/scientific-fidelity.md).
- **Structured application data:** dataclasses, Pydantic models, enums and binary
  values serialize as structured data. Tagged tuples, sets and frozensets restore
  their collection types. Model fields normalize to dictionaries; applications
  explicitly hydrate their own model classes.
- **Actionable failures:** serialization errors identify the responsible field,
  such as `$.results[2].value`, while preserving exception identity and causes.
- **LangGraph integration:** `datason.integrations.langgraph.DatasonSerializer`
  implements the checkpoint serializer protocol without adding a core LangGraph
  dependency. SQLite close/reopen/resume, dynamic interrupts and Send fan-out
  have regression coverage across two pinned SDK generations. An offline Agents
  SDK recipe verifies context hooks, dependency rebinding and approval resume.
  See the [framework matrix](../framework-compatibility.md). The
  adapter has its own `datason-json-v1` format; existing native checkpoints need
  an explicit migration rather than swapping serializers in place.
- **Security and policies:** integrity envelopes use versioned canonical JSON;
  keyed verification rejects hash-only downgrade. Pickle conversion requires
  explicit trust. Shared non-finite-value policies and input/reconstruction
  budgets apply across core and plugin data. Dense ML reconstruction checks
  shape/count/buffer limits, restores empty shapes and numeric bfloat16, and
  places Torch/TF tensors on CPU. Sparse pointer buffers are checked before
  allocation. JAX rejects implicit x64 narrowing; sklearn hydration requires an
  estimator class and dictionary state. Parser callbacks and JSON options
  have regression coverage, and packaging validation was expanded.

## Performance

Exact JSON primitives avoid unnecessary circular-reference bookkeeping after
budget checks. NumPy conversion chooses its representation before materializing
lists and batches supported complex-array conversion using NumPy operations.
The stock email redactor skips regex scanning on ordinary strings without `@`.

Against the main baseline immediately before the performance changes, the
shared CI benchmarks measured approximately **7% faster NumPy encoding,
11% faster decoding and 8% faster two-dimensional round trips** for their tested
payloads. Plain JSON timings were largely unchanged. These are workload-specific
measurements, not a speed comparison with other serializers or a promise for all
applications. The email change preserves matching behavior; arbitrary custom
regex execution remains outside that optimization.

## Upgrade notes

- **Pickle:** conversion APIs reject input unless called with `trusted=True`.
  Use that flag only for data from a trusted source. Module filters are diagnostic
  checks, not a safe-unpickling sandbox.
- **Mapping keys:** reserved type metadata keys and keys that collide after JSON
  normalization are rejected instead of silently changing the payload. Rename
  or explicitly convert those application fields before serialization.
- **Budgets:** serialized keys, metadata and plugin output count toward limits.
  New `max_input_bytes` and `max_nodes` limits also apply before reconstruction;
  array allocations are checked. Increase a limit deliberately for a known
  workload, rather than relying on the older incomplete accounting.
- **Plugin reconstruction:** `allow_plugin_deserialization=False` disables typed
  plugin reconstruction. Security checks do not sandbox custom plugins, parser
  hooks or model serializers. The built-in reconstruction review is complete for
  this source, but typed ML loads remain scoped to trusted application-owned
  snapshots and reviewed installed code. Per-buffer estimates do not cap peak
  or total process memory.
- **Non-finite values:** the default `NanHandling.NULL` normalizes NaN/Infinity to
  null, including supported plugin leaves. Choose an explicit policy and keep
  the consuming schema consistent with that representation.
- **Stored data:** 24 fixture payloads captured from the actual a1 release source
  cover standard/scientific values, fitted ML examples, diagnostic exports,
  custom tags and migration edge cases. Supported records replay; ambiguous
  legacy timestamps need known units, large dtype-less unsigned integers need
  authoritative dtype information, and custom-formatted legacy signatures need
  the original signed bytes. Old untagged collections remain lists. Missing
  historical type information cannot be recovered; the sample does not guarantee
  every historical payload or model/library combination.
- **API versus persistence:** untagged API output follows JSON normalization.
  Tagged internal snapshots have a different fidelity contract; turning tags off
  does not preserve all types or automatically validate a provider/tool schema.

## Validation and release status

The earlier fixes and release preparation (#122–#126) are merged. The P1
follow-up is merged, including [persisted formats #127](https://github.com/danielendler/datason/pull/127),
[ML reconstruction #128](https://github.com/danielendler/datason/pull/128),
and [framework compatibility #129](https://github.com/danielendler/datason/pull/129).
The P1 combined source passed **985 tests with no
skips and all 30 snapshots** locally using actual optional libraries and current
SDK pins. The matrix also exercises older SDK pins locally and in dedicated CI.
The combined wheel and sdist build and pass Twine checks. A fresh wheel
installation without optional dependencies passes core, six historical-payload,
integrity and adapter-without-LangGraph smoke checks. The changed runtime lines in #128 and #129 each reached 100% patch coverage;
main now requires 90%. Publication remains a separate release step.

This remains an alpha. Tool-schema validation and representative
performance/import measurements are prepared in P2 review PRs
[#131](https://github.com/danielendler/datason/pull/131) and
[#132](https://github.com/danielendler/datason/pull/132). The
[application evidence](../adoption-evidence.md) includes an author-owned financial
case; independent adoption and broader version coverage remain open on the
[hardening roadmap](../hardening-roadmap.md).

Once published, install the alpha explicitly:

```bash
pip install 'datason==2.0.0a2'
```
